# Rackbook · 机房手账（v1.4 · 星际舰队）

一个原生 macOS（SwiftUI）应用，用纸面手账的画风（马克笔 + 铅笔 + 墨线）监控和管理多台 Linux 服务器。每台服务器都是一艘舰船，你是船上的船员。

## v1.4 新增：可视化文件编辑器

在“文件”页双击任意文本文件，或者点“常用文件”里的 `~/.bashrc`、`/etc/hosts`、`sshd_config`、`daemon.json` 等，就会打开编辑器：

- **源码**：带行号；JSON、YAML、Shell、配置文件按语法用墨水和马克笔配色着色；⌘F 查找，⌘S 保存，支持撤销；长行不自动折行。
- **结构**（在源码旁边，或单独全宽显示）：
  - JSON：可折叠的树，保持原来的键顺序，标出类型和数量；可以一键“格式化”或“压缩”，键顺序不变
  - YAML：按缩进生成大纲
  - `.bashrc` 这类 shell 脚本：分成环境变量、PATH 搜索路径（逐条拆开）、别名、函数、引用的文件五类
  - 配置文件（ini、conf、env、sshd_config、hosts）：按节列出键和值
  - 纯文本：行数、换行符类型、行尾空白等概况
  - 点结构里任意一项，就跳到源码对应的行。
- **校验**：
  - JSON 在本地解析，能定位到第几行第几列
  - YAML 先查缩进里的 Tab，再可选用服务器上的 PyYAML 做完整校验
  - Shell 用服务器上的 `bash -n` 检查（zsh 文件用 `zsh -n`）
- **安全保存**：
  - 保存前默认备份为 `文件名.rackbook.bak`
  - 打开后如果服务器上的文件被改过，会先提醒
  - JSON 或 Shell 有语法错误时，会先确认再保存
  - 没有读写权限的系统文件，舰长可以用 sudo 读写；领航员只能查看
  - 二进制文件、非 UTF-8 文件和超过 1 MB 的文件，只读显示
- **新建文件**：在当前目录新建，保存时才真正写到服务器上。

## v1.3 新增

- **后台运行**：关闭主窗口（⌘W）或点侧栏的「转入后台 ⇧⌘B」后，Rackbook 会继续监控。这时 Dock 图标隐藏，菜单栏右上角出现一个舰船图标；有告警或失联时，图标旁边会显示数字。点图标会弹出后台值班面板：可以看各艘舰船的 CPU 和内存，打开主窗口，开关悬浮窗，进入设置，全部接通或全部断开，或者退出。在 Finder 或 Spotlight 里再次打开 Rackbook 也能回到主窗口。如果希望关闭窗口就直接退出，可以在设置里关掉后台运行。
- **悬浮窗**（可选）：只在转入后台后弹出，回到主窗口时自动收起。窗口置顶，在所有桌面都可见，任意位置拖动即可移动，位置会被记住。双击某艘舰船即可登舰，右键菜单里可以进入设置或隐藏悬浮窗。
- **悬浮窗可配置**（⌘, 设置）：
  - 样式：列表或小舰船
  - 指标：CPU、内存、网络、磁盘、显卡、负载，任意组合
  - 舰船：全部，或者只选其中几艘
  - 只显示需要留意或失联的舰船
  - 纸张不透明度
  - 把悬浮窗放回右上角

## v1.2 新增

- **密码登录**：每个登舰账户都可以选择“密钥 / ssh-agent”或“密码”。密码只存在 macOS 钥匙串里。建立连接时，Rackbook 会通过 `SSH_ASKPASS` 自己从钥匙串读出密码交给 ssh，只用这一次；之后的采集、命令、文件传输和“在终端打开”都复用这条已认证的连接。sudo 密码留空时，默认与登录密码相同。

## v1.1 新增

- **星际舰队总览**：一张手绘星图，舰船排成 V 字编队航行。舰级按规模划分为侦察艇、护卫舰、巡洋舰、母舰，核数最多的在航舰船是旗舰。尾焰长度随 CPU 负载变化，颜色从蓝到金再到红；忙碌或吃紧时舰船会亮起虚线护盾；舰船之间的蓝点是网络流量。已断开的舰船停在底部的“空港”。点任意一艘舰船即可登舰。
- **主动断开 / 接通**：断开会停止采集，并关闭 SSH 复用连接（`ssh -O exit`）。断开状态在重启应用后仍然保留。总览页提供“全部断开 / 全部接通”，退出应用时也会关闭所有连接。
- **账户角色（舰长 / 领航员）**：一艘船可以挂多个登舰账户，在右上角随时切换。角色根据 sudo 权限自动判定：root、免密 sudo，或在 sudo/wheel 组里并且已存 sudo 密码的账户是**舰长**；没有 sudo 的是**领航员**。需要 sudo 的操作（重启服务、通过 sudo 使用 Docker、调整船员角色）会拒绝领航员，并说明原因。sudo 密码只存在 macOS 钥匙串里。
- **船员 · 权限**页：
  - 管理这台 Mac 上的登舰账户：切换账户、重新查验权限、存或删除 sudo 密码。
  - 列出服务器上的真实账户及其角色。舰长可以把账户升为舰长或降为领航员（调整 sudo/wheel 组），也可以把账户加入或移出 docker 组（“货舱”）。不允许把正在使用的账户降级，避免把自己锁在门外。
- **Docker 货舱**：每个容器画成一个货柜，显示状态、CPU、内存、网络、端口，可以启动、停止、重启、删除、查看日志。还能管理镜像。页面每 6 秒自动刷新。账户在 docker 组里时直接操作，否则由舰长通过 sudo 操作。
- **显卡**：拆解图里多了一张显卡，风扇转速随占用变化，侧边有负载条，多块显卡会标出数量。数据来自 nvidia-smi（NVIDIA）或 sysfs（AMD）。没有显卡时画成一个虚线的空 PCIe 槽。聚焦面板里列出每块显卡的占用、显存、温度和功耗，另有一张显卡占用曲线。

- **不装 agent**：直接调用 Mac 自带的 `/usr/bin/ssh`，按需读取服务器上的 `/proc`、`df`、`ps`。所以 `~/.ssh/config` 里的别名、密钥、ssh-agent、跳板机都能直接用。每台服务器常驻一个 SSH 复用连接（ControlMaster），刷新开销很小。
- **舰队总览**：每台服务器一张卡片，上面有一台小小的等轴测机箱，以及 CPU、内存、磁盘的马克笔条、CPU 小曲线和告警。
- **拆解图**（借鉴 teardown / machine）：一台可以“拆开”的服务器。盖板掀起、硬盘抽出、网卡和电源后退，每个部件由实时数据驱动：散热器顶面按 CPU 负载变色，内存条按占用比例点亮，硬盘托架上画出各挂载点的用量，网线上蓝点（下行）、红点（上行）的流速随流量变化，风扇转速随 CPU 变化（示意）。页边用引线标注，点任一部件即可聚焦。
- **曲线**：CPU、内存、网络、磁盘读写，用手绘风格画出最近 150 次采样。
- **进程 · 服务**：进程按 CPU 或内存排序，可筛选，能发 SIGTERM / SIGKILL（会先确认）。另外可以列出 systemd 中正在运行的服务，查看日志，重启或停止服务（非 root 用户会走 `sudo -n`）。
- **文件**：浏览目录、跳转路径、预览和编辑文本文件（512 KB 以内可以直接保存回服务器）、新建文件夹、改名、删除（会先确认）、计算大小、下载到 Mac。从 Finder 拖进来即可上传（scp）。
- **命令**：像一卷收据纸，逐条执行非交互命令并保留输出。另有常用命令片段，以及“在终端打开”完整的交互会话。
- **状态栏**：每次操作都用一句话说明发生了什么；不允许的操作会给出理由，比如“还不行：web-01 还没接通……”。

## 构建与安装（.pkg 覆盖安装）

要求 macOS 14 及以上，并安装 Xcode 或 Command Line Tools（`xcode-select --install`）。

```bash
cd Rackbook
./build.sh                    # 生成 Rackbook.app 和 Rackbook-1.4.1.pkg
open Rackbook-1.4.1.pkg         # 或：sudo installer -pkg Rackbook-1.4.1.pkg -target /
```

安装包始终装到 `/Applications/Rackbook.app`，会覆盖已有版本（组件不可重定位，覆盖方式为 upgrade；每次构建号都会更新）。安装前会自动退出正在运行的 Rackbook。服务器列表和钥匙串里的密码不受影响。

## 服务器要求

- Linux，可以用密钥 / ssh-agent 登录，也可以用密码登录（需要服务器开启 PasswordAuthentication 或 keyboard-interactive）。
- 首次连接会自动信任新主机指纹（`StrictHostKeyChecking=accept-new`）；如果指纹发生变化，会拒绝连接。
- 文件列表依赖 GNU `find -printf`（主流发行版都有；BusyBox / Alpine 上需要安装 `findutils`）。

## 字体（可选）

界面会优先使用 tinycharts 的字体：**Gaegu**（手写）、**Courier Prime**（数字）、**Young Serif**（标题）。如果系统里没有，则回退到 macOS 自带的 Noteworthy、Courier New 和 Baskerville。想要原汁原味，可以从 Google Fonts 安装这三款字体，然后重启应用。

## 数据存放

服务器列表保存在 `~/Library/Application Support/Rackbook/servers.json`，SSH 复用套接字放在 `/tmp/rackbook-<uid>/`。
